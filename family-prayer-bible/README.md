# 우리 가족 기도말씀 30

카카오톡 공지의 링크 하나로 가족 3명이 순서대로(아빠 → 엄마 → 딸) 한글 성경을 읽고,
같은 화면에서 영어 성경을 원어민 음성(Web Speech API)으로 듣는 모바일 우선 PWA입니다.

외부 프레임워크, 로그인, 서버, API 키 없이 순수 HTML/CSS/JavaScript로만 동작합니다.

---

## 1. 앱의 목적

- 가족이 정해진 순서(아빠 → 엄마 → 딸, 반복)대로 기도 관련 성경 구절을 함께 읽습니다.
- 각 구절마다 한글 본문은 직접 소리 내어 읽고, 영어 본문은 '영어 듣기' 버튼으로 원어민 음성을 듣습니다.
- 카카오톡 공지 링크 하나로 접속해서 회원가입 없이 바로 사용할 수 있습니다.
- 진행 상황은 기기의 localStorage에 저장되어, 앱을 닫았다 열어도 이어서 읽을 수 있습니다.
- 첫 화면에는 두 개의 주요 버튼이 있습니다: **기도**(구절을 순서대로 읽기 시작) / **말씀추가**(새 구절을 직접 입력해
  목록에 추가). 기본 30구절 외에 가족이 원하는 구절을 계속 추가하며 사용할 수 있습니다.

## 2. 파일별 역할

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조(첫 화면·읽기 화면·완료 화면·오류 화면 등) |
| `styles.css` | 모바일 우선 반응형 디자인, 크림/네이비/골드 배색, 다크모드 대응 |
| `app.js` | 화면 전환, 가족 교대 로직, 음성 재생 제어, localStorage 저장, 데이터 검증 |
| `verses.js` | 30개 성경 구절 데이터(`BIBLE_VERSES`)와 번역본 정보(`BIBLE_TEXT_META`) |
| `manifest.json` | PWA 설치 정보 (앱 이름, 아이콘, 테마 색상 등) |
| `service-worker.js` | 오프라인에서도 이미 열어본 화면이 동작하도록 앱 파일을 캐시 |
| `icons/icon-192.svg`, `icons/icon-512.svg` | 홈 화면/설치 아이콘 |

## 3. 로컬 실행 방법

이 앱은 서비스워커(PWA 오프라인 기능)를 사용하므로, `index.html`을 더블클릭해서
`file://`로 여는 방식은 서비스워커가 등록되지 않아 오프라인 기능이 정상 동작하지 않을 수 있습니다.
(화면 표시, 성경 읽기, 음성 재생 등 핵심 기능은 file://에서도 대부분 동작하지만, 정확한 테스트를 위해
아래처럼 로컬 서버로 실행하는 것을 권장합니다.)

터미널에서 `family-prayer-bible` 폴더로 이동한 뒤, 아래 중 하나를 실행하세요.

```bash
# Python 3가 설치되어 있는 경우
python3 -m http.server 8000

# Node.js가 설치되어 있는 경우
npx serve .
```

이후 브라우저에서 `http://localhost:8000` 으로 접속합니다.

## 4. 성경 본문 입력·수정 방법

`verses.js` 파일의 `window.BIBLE_VERSES` 배열을 수정합니다. 각 항목은 아래 구조를 반드시 지켜야 합니다.

```js
{
  id: 1,                                   // 1~30, 중복 불가
  referenceKo: "빌립보서 4장 6절",           // 한글 장·절
  referenceEn: "Philippians 4:6",          // 영문 장·절
  korean: "한글 본문",                      // 실제 번역본 원문 그대로
  english: "English text"                  // 실제 번역본 원문 그대로
}
```

- 4개 필드(`referenceKo`, `referenceEn`, `korean`, `english`) 중 하나라도 비어 있으면
  앱 시작 시 자동 검증에서 실패로 처리되어 "성경 데이터에 누락 또는 오류가 있습니다" 오류 화면이 표시됩니다.
- 본문에 HTML 태그나 스크립트로 의심되는 내용이 포함되면 검증에서 오류로 표시됩니다.
- 번역본을 변경한 경우, `window.BIBLE_TEXT_META`의 `koreanVersionName`/`englishVersionName`/저작권 고지 문구도
  실제 사용한 번역본에 맞게 함께 수정해야 합니다. (아래 11번 항목 참고)

**앱 안에서 구절 추가하기('말씀추가' 기능)**

`verses.js`를 직접 편집하지 않고도, 첫 화면의 '말씀추가' 버튼으로 새 구절을 추가할 수 있습니다.
권(책 이름)·장·절과 한글/영어 본문을 직접 입력하면 기존 목록 뒤에 새 번호(31번, 32번, …)로 저장됩니다.
이 앱은 외부 성경 API나 서버를 사용하지 않으므로(요구사항: API 키/서버 없이 동작), 책/장/절만 입력하면
본문이 자동으로 채워지는 기능은 없습니다 — 본문은 반드시 실제 성경에서 그대로 옮겨 직접 입력해야 합니다.
추가한 구절은 이 기기의 localStorage에 저장되며(다른 기기와 자동으로 공유되지 않음), '처음부터 다시 시작'으로
읽기 기록을 초기화해도 삭제되지 않습니다.

## 5. 가족 이름 기본값 변경 방법

기본값은 `app.js` 상단의 다음 부분입니다.

```js
var DEFAULT_NAMES = ['아빠', '엄마', '딸'];
```

이 배열의 순서가 그대로 1번째·2번째·3번째 읽는 사람이 되며, 구절 번호를 3으로 나눈 나머지로
자동 배정됩니다. 사용자는 첫 화면의 '가족 이름 설정'에서 직접 이름을 바꿀 수 있고,
바꾼 이름은 이 기기의 localStorage에 저장되어 계속 사용됩니다.

## 6. 음성이 나오지 않을 때 해결 방법

1. 이 앱은 브라우저 내장 기능인 **Web Speech API(speechSynthesis)**를 사용합니다.
   별도 설치나 API 키가 필요 없지만, 브라우저/기기가 지원해야 합니다.
2. 음성이 전혀 나오지 않으면: 기기의 음소거 스위치, 미디어 볼륨을 먼저 확인하세요.
3. 카카오톡 인앱 브라우저에서 소리가 나오지 않으면, 화면 우측 상단(또는 하단) 메뉴에서
   **"다른 브라우저로 열기"(Chrome/Safari 등)**를 선택해 실행해 보세요. 인앱 브라우저는
   음성합성 지원이 기기/버전마다 다를 수 있습니다.
4. 음성 목록이 설치되어 있지 않은 안드로이드 기기는 "설정 > 접근성(또는 일반) > 텍스트 음성 변환"에서
   Google 음성 데이터(영어)를 설치해야 할 수 있습니다.
5. 음성합성을 전혀 지원하지 않는 환경에서는 '영어 듣기' 버튼 대신 안내 문구가 표시되고,
   화면에 보이는 영어 본문을 직접 읽으면 됩니다. 이 경우에도 '다음 말씀' 버튼은 정상적으로 눌러
   다음으로 진행할 수 있습니다.

## 7. 카카오톡 인앱 브라우저 사용 방법

- 카카오톡 공지사항이나 채팅방에 올린 링크를 누르면 카카오톡 내장 브라우저로 바로 열립니다.
- 화면 표시, 한글/영어 본문 읽기, 다음/이전 이동, 진행 저장은 인앱 브라우저에서도 동작합니다.
- 음성 재생이나 PWA 설치가 원활하지 않다면, 우측 상단 "···" 메뉴에서 "다른 브라우저로 열기"를 선택하세요.

## 8. 홈 화면에 추가하는 방법

**iOS(Safari):** 공유 아이콘(사각형 위 화살표) → "홈 화면에 추가" → 추가
**Android(Chrome):** 우측 상단 "⋮" 메뉴 → "홈 화면에 추가" 또는 "앱 설치"

카카오톡 인앱 브라우저에서는 "다른 브라우저로 열기"로 먼저 이동한 뒤 홈 화면에 추가하는 것을 권장합니다.

이 프로젝트는 빌드 과정이 없는 순수 정적 파일이므로, `family-prayer-bible` 폴더 전체를
아래와 같은 정적 호스팅 서비스에 그대로 업로드하면 됩니다.

**GitHub Pages — 이 저장소는 이미 배포되어 있습니다**

이 저장소에는 `.github/workflows/deploy-pages.yml` 워크플로가 포함되어 있어,
`claude/family-prayer-bible-pwa-l0186s` 브랜치의 `family-prayer-bible/` 폴더에 변경이 생길 때마다
GitHub Actions가 자동으로 GitHub Pages에 배포합니다(저장소 Settings → Pages → Source가
"GitHub Actions"로 설정되어 있어야 합니다. 이미 설정 및 배포 완료).

**실제 배포 주소:** https://ddase11.github.io/success/

다른 저장소에 처음부터 새로 배포하려면:
1. GitHub 저장소에 `family-prayer-bible` 폴더의 내용을 푸시합니다.
2. 저장소 Settings → Pages → Source를 "Deploy from a branch"로 두고 배포할 브랜치/폴더를 고르거나,
   이 저장소처럼 GitHub Actions 워크플로(`.github/workflows/deploy-pages.yml`)를 추가하고
   Source를 "GitHub Actions"로 선택합니다.
3. 발급된 `https://사용자명.github.io/저장소명/` 주소로 접속해 정상 동작을 확인합니다.

**Cloudflare Pages**
1. Cloudflare Pages에서 새 프로젝트를 만들고 저장소를 연결하거나, 폴더를 직접 업로드합니다.
2. 빌드 명령 없이 "정적 사이트"로 배포합니다(빌드 출력 디렉터리 = `family-prayer-bible`).

두 방법 모두 HTTPS가 자동 적용되어 Web Speech API, 서비스워커, PWA 설치가 정상 동작합니다.

  검색으로 확인한 문구를 그대로 옮긴 것이며, 개발자가 임의로 창작하거나 기억에 의존해 작성하지 않았습니다.

## 12. 테스트한 환경과 남아 있는 제한사항

### 실제로 수행한 검사
- Node.js `node --check`로 `app.js`, `verses.js`, `service-worker.js`의 자바스크립트 구문 오류 여부를 확인했습니다(통과).
- `verses.js`의 30개 구절에 대해 개수(30개), id 1~30 중복 없음, 4개 필수 필드(`referenceKo`/`referenceEn`/`korean`/`english`)
  비어있지 않음, HTML/스크립트 태그 미포함 여부를 검증하는 스크립트를 실행해 통과를 확인했습니다.
- `manifest.json`을 `JSON.parse`로 파싱해 형식 오류가 없음을 확인했습니다.
- `service-worker.js`가 캐시하는 경로 목록이 실제 프로젝트 파일과 일치하는지 확인했습니다.
- Python 내장 HTTP 서버(`python3 -m http.server`)로 로컬 구동 후, Playwright(Chromium)로 아래 4가지
  모바일/태블릿 화면 크기에서 실제 사용자 흐름을 자동으로 실행해 확인했습니다: 360×800, 390×844, 412×915, 768×1024.
  각 화면 크기에서 다음을 모두 확인했습니다.
  - 첫 화면 표시 및 데이터 오류 화면 미표시(데이터 검증 통과)
  - 가족 이름 3명 입력 및 저장
  - 3/5/10/30구절 분량 선택 버튼 동작
  - "가족 성경 읽기 시작" 후 읽기 화면 진입, 1번 구절 담당자(첫 번째 이름) 표시
  - 한글/영어 본문 표시, '다음 말씀' 버튼이 듣기 전에는 비활성화되어 있음
  - 일시정지·이어 듣기·다시 듣기·음성 정지·속도(0.8배/1.0배) 버튼 동작 및 존재
  - 영어 듣기 후(재생 종료 또는 오류 발생 시) '다음 말씀' 버튼이 활성화됨
  - 다음 말씀 이동 시 진행 상태 텍스트 갱신과 담당자가 아빠→엄마→딸 순서로 자동 교체됨
  - 이전 말씀 이동 시 진행 상태와 담당자가 정확히 재계산됨
  - 이미 읽은 구절로 돌아온 뒤 '다음 말씀' 버튼을 5회 연속(동기적으로) 눌러도 한 구절만 전진함(중복 이동 방지 확인)
  - 선택한 분량(3구절) 완료 후 완료 화면에 오늘 읽은 구절 수/전체 완료 구절 수/다음 시작 구절 번호가 정확히 표시되고,
    30구절을 다 읽지 않았을 때는 축하 문구가 숨겨져 있음
  - 완료 화면에서 처음 화면으로 이동 후 새로고침해도 "4번부터 시작" 안내가 유지됨(진행 기록 저장/복원)
  - '처음부터 다시 시작' 클릭 시 확인창이 뜨고, 취소를 누르면 기록이 삭제되지 않음
  - 뷰포트 폭 기준 가로 스크롤이 발생하지 않음(작은 화면에서 텍스트가 잘리지 않음)
  - 테스트 중 발생한 브라우저 콘솔 로그를 모두 수집해 확인
- 이 자동화 테스트 과정에서 **실제 버그 2건을 발견해 수정**했습니다.
  1. `[hidden]` 속성이 지정된 화면 요소들이 `.screen`/`.dialog-overlay` 클래스의 `display: flex` 규칙에 가려
     실제로는 사라지지 않고 여러 화면이 겹쳐 보이는 문제 → `styles.css`에 `[hidden] { display: none !important; }`
     규칙을 추가해 수정했습니다.
  2. 브라우저의 음성 엔진이 `onend`나 `onerror` 콜백을 전혀 호출하지 않고 멈춰버리는 경우(테스트 환경에서 재현됨),
     사용자가 '다음 말씀' 버튼을 영영 누르지 못하고 멈추는 문제 → `app.js`의 음성 재생 로직에 15초 감시
     타이머(watchdog)를 추가해, 응답이 없으면 자동으로 오류로 처리하고 다음 단계로 진행할 수 있게 했습니다.
- 실제 실행 중인 헤드리스 브라우저에는 시스템 음성엔진이 설치되어 있지 않아 영어 듣기 버튼을 누르면
  항상 `synthesis-failed` 오류가 발생합니다. 이는 테스트 환경의 제약이며, 이 오류가 발생했을 때도 앱이
  안내 문구를 보여주고 '다음 말씀' 버튼을 정상적으로 활성화하는 오류 복구 동작 자체는 확인했습니다.
  다만 실제 음성이 재생되어 끝까지 들리는 것 자체는(음성 엔진이 없어) 이 환경에서 직접 들어보지 못했으므로,
  실제 스피커로 들리는 음질·목소리는 실제 모바일 기기에서 추가로 확인이 필요합니다.
- 색상 대비를 WCAG 공식으로 직접 계산해 확인했습니다(예: 네이비 텍스트/크림 배경 13.18:1, 골드 텍스트/카드 배경
  4.86:1 등). 이 과정에서 장·절 표시에 쓰인 골드 색상의 대비가 다소 낮은 것을 발견해 텍스트 전용으로
  더 진한 골드 색상(`--color-gold-text`)을 추가하고 교체했습니다.

### 알려진 제한사항 (남아있는 항목)
- Web Speech API의 실제 음성 목록과 음질은 브라우저·OS·기기에 따라 크게 달라집니다.
  "en-US + Natural" 음성이 없는 기기에서는 우선순위에 따라 차선 음성이 자동 선택됩니다.
  실제 스피커로 들리는 음성 품질은 이번 자동화 테스트로 확인하지 못했으므로, 배포 후 실제 기기에서 들어봐야 합니다.
- 카카오톡 인앱 브라우저의 음성합성 지원 여부는 기기/카카오톡 버전에 따라 다를 수 있어,
  실제 배포 후 가족이 사용하는 기기에서 추가 확인이 필요합니다.
- iOS Safari의 apple-touch-icon은 SVG를 완벽히 지원하지 않는 버전이 있을 수 있습니다.
  더 선명한 아이콘이 필요하면 192×512 PNG로 별도 변환해 교체하는 것을 권장합니다.
- 한글 개역개정 본문의 공식 사용 허가 확인은 아직 완료되지 않았습니다(11번 항목 참고).
- 서비스워커 오프라인 동작은 로컬 서버 기준으로 캐시 등록/경로 일치만 확인했으며, 실제 배포 후
  비행기 모드 등에서의 완전한 오프라인 재접속 테스트는 별도로 수행하지 않았습니다.
